# RideShare M2 (Maps) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace M1's fixed city list with real place search anywhere in India, compute and store driving routes, and show the approved styled map on the trip page, the search results and the publish form.

**Architecture:** All external geo calls (Photon geocoding, OSRM routing) go through one server-side `geo` module with a pluggable provider (`live` or `fake`) and a Postgres-backed cache; failures fall back to the M1 city list or a straight line, never an error page. The map is one client component (`RouteMap`, MapLibre GL) rendering a hand-written vector style built from the design tokens, reading OpenFreeMap tiles; tests run with tiles off and the fake provider so nothing depends on the network.

**Tech Stack:** M1 stack plus `maplibre-gl` (latest 5.x, pinned exact) and `@mapbox/polyline` (pinned exact). Photon (`photon.komoot.io`), OSRM public server (`router.project-osrm.org`), OpenFreeMap (`tiles.openfreemap.org`) — all free, no keys.

**Spec:** `docs/superpowers/specs/2026-10-28-rideshare-design.md` (§3, §4 GeoCache, §5.1–5.2, §9.3, §9.6, §10.1–10.2). M1 code is the baseline; deferred items in `docs/superpowers/m1-followups.md` marked "M2" are in scope here.

## Global Constraints

- All Photon/OSRM calls happen server-side in `src/modules/geo/**` only; no other module or any client code calls them.
- Provider selected by env `GEO_PROVIDER` = `live` (default) | `fake`. Unit, integration and e2e tests and CI always use `fake`.
- Tiles toggle: env `NEXT_PUBLIC_MAP_TILES` = `on` (default) | `off`. With `off` the style has only the background and our own layers (no external requests). E2E and CI use `off`.
- India bounding box (used for Photon `bbox`, result filtering and server-side place validation): lng 68.1–97.4, lat 6.5–35.7. Invalid place → `VALIDATION` "Choose a place in India".
- Cache TTLs (spec §4): autocomplete and reverse 24 h; routes 30 days. Errors and `null` results are never cached.
- Timeouts: Photon 4 s, OSRM 6 s (`AbortSignal.timeout`). Send header `User-Agent: RideShare/1.0 (portfolio demo)`.
- Geo autocomplete rate limit (spec §10.2): 30/min per user, or per client IP when signed out; key `geo:<userId>` / `geo:ip:<ip>`; exceeding it returns the fallback list, not an error.
- Routes are stored as OSRM `overview=simplified` geometry encoded as **polyline6** (`@mapbox/polyline` precision 6); `distanceKm` rounded to 1 decimal, `durationMin` = `Math.ceil(seconds / 60)`.
- Map look exactly per spec §9.6: land `#f3efe9`, water `#cfe1e6`, minor roads white, highways `#e6dccf`, muted labels; dark variant from the dark tokens (§9.2); route line `--brand` with a `--surface` casing; pickup = ring in `--fg`; destination = filled `--brand` dot. Attribution "© OpenFreeMap © OpenStreetMap contributors" always visible.
- A trip with no stored route draws a dashed straight line between its points; no page ever fails because geo data is missing.
- Under `prefers-reduced-motion`: no route draw-in animation and no animated camera moves (`jumpTo`, not `flyTo`).
- Every M1 Global Constraint still applies (Result/ErrorCode, money in paise, IST, business rules in services, commit per task).

## Review Focus

1. **Photon or OSRM down/slow** — autocomplete still shows matching places from the M1 list; publishing still succeeds and stores no route; the trip page shows a straight dashed line. (Tasks 1, 4)
2. **Odd Photon results** — places outside India, duplicates (same label within ~50 m), and features missing a name are dropped; labels stay readable ("Sindhi Camp, Jaipur"). (Task 1)
3. **Fast typing** — debounce + 2-character minimum + cache keep normal typing well under 30 requests/min, and a late response never replaces a newer one. (Task 2)
4. **Theme switch while a map is open** — switching light/dark/system re-styles the map and keeps the route and pins. (Task 3)
5. **Polyline precision** — polyline6 decoded as polyline5 puts the route in the ocean; round-trip test pins precision. Trips from M1 with `routePolyline = null` render the straight-line fallback. (Tasks 1, 3)

**Interfaces:**
- Produces (`providers/index.ts`): `getProvider(): GeoProvider` — memoised by `GEO_PROVIDER`.
- Produces (`types.ts`):
  - `type LatLng = { lat: number; lng: number }`, `type Place = { label: string; lat: number; lng: number }` (re-exported from `cities.ts` so M1 imports keep working)
  - `type PlaceSuggestion = Place & { detail: string | null }` — `detail` e.g. "Rajasthan"
  - `type RouteInfo = { polyline: string; distanceKm: number; durationMin: number }`
  - `interface GeoProvider { search(q: string, limit: number): Promise<PlaceSuggestion[]>; reverse(p: LatLng): Promise<PlaceSuggestion | null>; route(a: LatLng, b: LatLng): Promise<RouteInfo | null> }` — providers throw on network/HTTP errors; `null`/`[]` mean "no result".
- Produces (`bounds.ts`): `INDIA_BBOX = { minLng: 68.1, minLat: 6.5, maxLng: 97.4, maxLat: 35.7 }`, `inIndia(p: LatLng): boolean`, `placeSchema` (zod: label trimmed 1–120, lat/lng numbers, refine `inIndia` → "Choose a place in India").
- Produces (`cache.ts`): `cached<T>(key: string, ttlMs: number, fn: () => Promise<T | null>): Promise<T | null>` — returns an unexpired row's JSON, else calls `fn`, stores non-null results (upsert), returns. Expired rows are overwritten, not deleted in bulk.
- Produces (`polyline.ts`): `encode6(points: LatLng[]): string`, `decode6(polyline: string): LatLng[]`, `toLineString(polyline: string): GeoJSON.LineString` (coordinates `[lng, lat]`).
- Produces (`service.ts`, the public API):
  - `searchPlaces(q: string): Promise<PlaceSuggestion[]>` — trims; `< 2` chars → `[]`; key `place:<lowercased q>`; provider errors → `searchCityList(q)` mapped to suggestions with `detail: null`; results filtered `inIndia`, deduped (same lowercased label and < 50 m apart), max 8.
  - `reversePlace(p: LatLng): Promise<PlaceSuggestion | null>` — `p` outside India → `null`; key `rev:<lat5>,<lng5>` (5-decimal rounding); error → `null`.
  - `route(a: LatLng, b: LatLng): Promise<RouteInfo | null>` — key `route:<a5>;<b5>`; error → `null` (logged with `logger.warn`).
  - `haversineKm` unchanged.
- Photon mapping: request `GET https://photon.komoot.io/api/?q=<q>&limit=10&lang=en&bbox=68.1,6.5,97.4,35.7`; each feature → label = `name` + (`, ` + first of `city` | `county` | `state` that differs from `name`), `detail` = `state ?? null`, coords from `geometry.coordinates [lng, lat]`; features without `name` dropped. Reverse: `GET /reverse?lat=&lon=&lang=en`, same mapping.
- OSRM mapping: `GET https://router.project-osrm.org/route/v1/driving/<lng>,<lat>;<lng>,<lat>?overview=simplified&geometries=polyline6`; `code !== 'Ok'` or no routes → `null`.
- Fake provider (deterministic, no network): search = `searchCityList(q)` with `detail: 'Fake'`; reverse = nearest `CITIES` entry within 25 km else `null`; route = straight 3-point polyline6 (a, midpoint, b) with `distanceKm = round1(haversine × 1.25)`, `durationMin = ceil(distanceKm / 50 × 60)`.
